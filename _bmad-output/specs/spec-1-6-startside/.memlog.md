- (note) Modus: express – input er rik (story-AC, EXPERIENCE Fast mikrotekst og Emotional Beats, epic-1-context UX & Interaction Patterns, kode fra 1.3/1.4, midlertidig Start i PR #8)
- (capability) CAP-1 Innhold på Start: display «Du har sannsynligvis mer erfaring enn du tror.», én forklarende setning og personvernteksten ordrett fra EXPERIENCE Fast mikrotekst; success: teksten rendres ordrett, overskriften er eneste h1, og ingen annen tekst på siden lover noe om lagring eller sletting
- (capability) CAP-2 Avkrysning: avkrysningsboks merket «Jeg har lest dette og vil starte.» som kan brukes med mus og tastatur; success: label er koblet til boksen, klikk på teksten og Space krysser av, og avkrysningen styrer bare «Start ny økt»
- (capability) CAP-3 Start ny økt: aktiv bare når boksen er krysset av og GET /api/status gir harNokkel=true; trykk gir ny tom økt i modus ekte og navigering til /samtale; success: ren funksjon gir deaktivert for alle kombinasjoner unntatt avkrysset+nøkkel; trykk dispatcher startOkt(ekte) og router.push(/samtale)
- (capability) CAP-4 Prøv demomodus: aktiv når harDemodata=true, uavhengig av avkrysning; trykk gir ny tom økt i modus demo og navigering til /samtale; success: ren funksjon gir aktiv demo uten avkrysning når harDemodata, deaktivert ellers
- (capability) CAP-5 Statusmeldinger: uten nøkkel vises «Ingen API-nøkkel funnet. Se README, eller prøv demomodus.», uten demodata «Demodata mangler. Se README.»; success: meldingene vises bare i de tilfellene og er koblet til sin knapp med aria-describedby
- (constraint) Bruker GET /api/status fra 1.4, validert med StatusSvar fra kjerne/skjema; klient importerer ikke server og ikke zod direkte (eslint-grensene)
- (constraint) Kontrakt mot 1.8 (PR #8) beholdes: dispatch({ type: 'startOkt', modus }) og router.push('/samtale')
- (decision) Har økten allerede modus (studenten kom tilbake til Start), dispatches nyOkt før startOkt, fordi startOkt ignoreres når modus er satt og AC krever en ny, tom økt
- (decision) Mens status lastes er begge knappene deaktivert og ingen statusmelding vises; feiler kallet eller er svaret ugyldig, behandles det som harNokkel=false og harDemodata=false, så ingen knapp lover noe serveren ikke kan levere
- (decision) Tekstene (display, forklaring, personverntekst, avkrysning, statusmeldinger) står som konstanter i src/klient/start/tekster.ts, ikke i kjerne/regler.ts (Victoria: ikke rør regler.ts; EXPERIENCE tillater Start-komponenten)
- (decision) Forklarende setning: «Du svarer på noen åpne spørsmål om det du har gjort, og Erfaringsgruven kobler svarene dine til kravene i en stillingsannonse.»
- (decision) Avkrysning med shadcn Checkbox lagt til med shadcn-CLI og brukt uendret; reserve er native input type=checkbox hvis CLI-en ikke kan hentes
- (decision) Visningen Startflate er ren (props: status, avkrysset, hendelser); src/app/page.tsx henter status, eier avkrysningen og dispatcher; tekst og deaktivering testes med renderToString uten DOM
- (constraint) Ingen localStorage/sessionStorage/IndexedDB/cookies; avkrysningen lever bare i komponenttilstand
- (constraint) WCAG 2.2 AA: én h1, label koblet til avkrysningen, statusmeldinger koblet med aria-describedby, alt med tastatur, fokusring fra shadcn, DOM-rekkefølge = leserekkefølge
- (constraint) Visuelt: én kolonne sentrert, maks column-max, type-display på overskriften, primærknapp for «Start ny økt», outline for «Prøv demomodus»; ingen stegindikator på Start (skallet gjelder flater etter Start)
- (assumption) /samtale finnes først når 1.8 (PR #8) er merget; før det gir navigeringen 404, og det godtas
- (assumption) Demoflyten etter start (demobanner, Neste) hører til 1.13; Start setter bare modus demo
