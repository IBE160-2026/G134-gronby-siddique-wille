- (direction) Victoria: lag spec for Story 1.10 fra docs/epics.md i samme format som tidligere SPEC.md (companions DESIGN.md, EXPERIENCE.md, epic-1-context.md); bygg videre på src/kjerne/regler.ts uten å røre det som finnes; koble inn i src/app/api/samtale/route.ts (Rikkes 1.8), behold feilmodell og eksisterende tester; ikke rør src/klient/ eller 1.11-kode; kvalitetssjekk mot AC og rett avvik selv; implementer, kjør test/lint/build, commit på norsk
- (note) Modus: express – input er rik (story-AC, AD-7/AD-15/AD-16 i ARCHITECTURE-SPINE, ordlyd i EXPERIENCE.md, eksisterende kode fra 1.4/1.8)
- (capability) CAP-1 Terskelkonstanter: regler.ts eksporterer MAAL_ERFARINGER = 3, MAKS_OPPFOLGING_PER_ERFARING = 3, MIN_ANNONSE_TEGN = 200, OVERGANGSSPORSMAL og STANDARD_REFLEKSJON; success: verdiene og ordlyden fra EXPERIENCE.md er testet, tekstene er innenfor MAKS_TEKST_TEGN
- (capability) CAP-2 erLukket: en erfaring er lukket når loggen har MAKS_OPPFOLGING_PER_ERFARING sporsmal med gjelder lik ID-en; spørsmål med gjelder null eller annen ID teller ikke; success: 2 → usann, 3 → sann, 4 → sann; null og andre ID-er teller ikke
- (capability) CAP-3 kanGaVidere: sann når antall fangede erfaringer ≥ MAAL_ERFARINGER (AD-7 via antallFangede); success: 2 fangede + 1 ufanget → usann, 3 fangede → sann; lukket erfaring med manglende felt teller ikke
- (capability) CAP-4 Overgang i /api/samtale: når modellens sporsmal.gjelder er en lukket erfaring, byttes spørsmålet ut med OVERGANGSSPORSMAL og gjelder null før svaret forlater serveren; endringer beholdes; success: rutetest med 3 oppfølgingsspørsmål om E1 og modellsvar gjelder E1 gir OVERGANGSSPORSMAL/null; 2 oppfølgingsspørsmål gir modellens spørsmål uendret
- (capability) CAP-5 Lukket påvirker ikke status: erLukket endrer verken erFanget eller antallFangede; success: test der lukket erfaring som mangler resultat gir erFanget usann og kanGaVidere uendret
- (decision) kanGaVidere = antallFangede ≥ MAAL_ERFARINGER som Victoria ba om (PRD FR-3, UX-DR7: «Gå videre til oppsummering» ved ≥3); ARCHITECTURE-SPINE sier «minst én fanget» – avviket føres som åpent punkt for 1.11/1.12 (sperre mot kravuttrekk ved 0 fangede trenger da egen regel)
- (decision) Byttet gjøres i en ren kjernefunksjon begrensOppfolging(svar, tilstand) i kjerne/endringer.ts ved siden av begrensSamtaleSvar; ruten kaller den etter begrensSamtaleSvar
- (decision) Er MAKS_ERFARINGER nådd samtidig, byttes spørsmål om en lukket erfaring med MAKS_ERFARINGER_SPORSMAL i stedet for OVERGANGSSPORSMAL, fordi overgangen ber om en ny erfaring som da ikke kan opprettes; gjelder er null i begge tilfeller
- (decision) Endringer i modellsvaret beholdes når spørsmålet byttes: studentens siste svar kan fortsatt fylle felt og kilder på den lukkede erfaringen; grensen stopper bare nye spørsmål (AC 2)
- (decision) Bare gjelder som er en E-ID (string) sjekkes; { ny } og null er nye erfaringer og kan ikke være lukket
- (decision) Ruten sender lukkede (E-ID-er for aktive lukkede erfaringer) til modellen i meldingen (ARCHITECTURE-SPINE AD-16), og prompts/samtale.md får en regel om ikke å spørre mer om dem; byttet i kjernen er garantien, prompten reduserer antall bytter
- (decision) Eksisterende rutetest «ekte: sender prompt…» utvides med lukkede: [] i forventet melding; ingen tester fjernes
- (constraint) Kjernefunksjonene er rene, uten I/O, og importerer aldri app/klient/server; eksisterende eksporter i regler.ts endres ikke
- (constraint) erLukket og kanGaVidere tar samme tilstandsform som kanTrykkeFerdig/erMaksNadd, så UI (1.11) og ruter bruker samme funksjoner
- (constraint) Feilmodellen i ruten er uendret; persondata havner aldri i logg eller feilsvar
- (constraint) Fagbegreper på norsk uten æøå i koden; UI-tekst med æøå ordrett fra EXPERIENCE.md
- (note) Ikke-mål: fremdriftsmåler og Ferdig/Gå videre-knapp (1.11), bruk av MIN_ANNONSE_TEGN i UI (2.1), bruk av STANDARD_REFLEKSJON (Epic 3), endringer i src/klient/, demodata
- (assumption) OVERGANGSSPORSMAL og STANDARD_REFLEKSJON hentes ordrett fra EXPERIENCE.md (ordlyden eies av UX)
- (assumption) Spørsmål om slettede erfaringer sjekkes også mot erLukket; klientens losGjelder gjør dem uansett til null
